# ADF4351 ESP32 Generator

Проект собран как стандартный PlatformIO-проект — по той же схеме, что и `gnss_esp32-s3`: сборка выполняется командой `pio run`, GitHub Actions публикует артефакт `esp32-firmware`.

## Получение готовой прошивки

1. Откройте вкладку **Actions** в GitHub.
2. Выберите последний успешный запуск **Build firmware**.
3. Внизу страницы скачайте артефакт **esp32-firmware**.
4. В архиве находятся `firmware.bin`, `bootloader.bin`, `partitions.bin`, `boot_app0.bin`, `flash_args.txt` с адресами записи и краткая информация о целевой плате.

Целевая плата: **ESP32 Dev Module / ESP32 DevKit V1 (38-pin)**, PlatformIO environment: `esp32dev`.

## Сборка и загрузка

Сборка выполняется PlatformIO, как в проекте GNSS: GitHub Actions запускает `pio run` и публикует артефакт `esp32-firmware`.

1. Откройте **Actions** и выберите последний успешный **Build firmware**.
2. Скачайте и распакуйте артефакт `esp32-firmware`.
3. Поместите `flash_windows.bat` рядом с четырьмя файлами `bootloader.bin`, `partitions.bin`, `boot_app0.bin`, `firmware.bin`.
4. Запустите `flash_windows.bat`, введите COM-порт. Скрипт установит esptool через Python при необходимости и прошьёт классический ESP32 DevKit V1.

Скрипт использует адреса записи: bootloader `0x1000`, partitions `0x8000`, boot_app0 `0xE000`, firmware `0x10000`. Это целевой **ESP32**, не ESP32-S3. Если плата не входит в режим загрузки автоматически, удерживайте BOOT, нажмите EN/RESET и отпустите BOOT.

Для разработки в VS Code можно открыть проект с PlatformIO и использовать **Upload** либо команды `pio run` и `pio run -t upload`.


Откройте репозиторий в VS Code с расширением PlatformIO, подключите ESP32 по USB и выполните **PlatformIO: Upload**. Для командной строки:

```bash
pio run
pio run -t upload
```

COM-порт обычно определяется автоматически. Если подключено несколько устройств, задайте его в `platformio.ini`, например `upload_port = COM5`.

Для просмотра Serial Monitor:

```bash
pio device monitor -b 115200
```

Arduino CLI и отдельный `FLASH.bat` больше не используются.

## Подключение ADF4351

| ADF4351 carrier | ESP32 DevKit V1 |
|---|---|
| CLK | GPIO18 |
| DAT | GPIO23 |
| LE | GPIO27 |
| CE | GPIO17 |
| LD | GPIO16 |
| MUX | GPIO34 (input only) |
| GND | GND |
| PDR | Leave unconnected |

Подключитесь к Wi-Fi **ADF4351-ESP32**, пароль **adf4351rf**, затем откройте **http://192.168.4.2**. Точка доступа использует статический адрес 192.168.4.2/24; роутер и интернет не нужны.

## Интерфейс

- **Generator:** частота 35–4400 MHz, RF ON/OFF, мощность, sweep.
- **Presets:** восемь ячеек энергонезависимой памяти.
- **Monitoring:** LD, MUX, число отправленных слов, время после записи, изменения LD, клиенты Wi-Fi, uptime и свободная память ESP32.
- **Settings:** скорость программно формируемого CLK и эвристический автоподбор.

## Ограничения диагностики

ADF4351 в этой схеме использует write-only 3-wire serial interface. Обычного SPI ACK или чтения регистров нет. Поэтому счётчик записей подтверждает только работу GPIO-кода ESP32, а LD/PLL Lock — косвенный признак работы синтезатора. Автоподбор скорости по LD является эвристикой, не подтверждением обмена.

## Электрическая безопасность

- До подачи питания проверьте назначение контакта 3V3 на конкретной плате: это может быть выход стабилизатора, а не вход питания.
- Убедитесь, что плата принимает логические уровни 3.3 V.
- Соедините земли ESP32 и платы ADF4351.
- Не подключайте RF-выходы AOUT+/AOUT- к GPIO. Используйте согласованную 50-омную нагрузку или RF-измерительное оборудование.
- Схема питания и уровни конкретной carrier-платы пока не подтверждены.

## Опорная частота и проверка

В прошивке задана опора 25.000 MHz (`REF_HZ`). Проверьте маркировку и фактическую частоту установленного генератора. Успешная компиляция не подтверждает точность RF-частоты или правильность аппаратного подключения. Прошивка требует проверки на реальной плате и измерения выхода подходящим прибором.
